# Yoru 0.9.9 — без API-ключей, Lordfilm и отдельные сериалы

## Фильмы и Lordfilm

Пользователь указал **https://sm.lordfilm5.pro/filmy/**. Для новых настроек раздела «Фильмы» выбран Lordfilm. Кнопка открывает **сам каталог сайта в отдельном окне Yoru**. Поиск, постеры, выбор фильма, качество, перевод, сезоны и серии находятся на странице источника. Это не импорт карточек Lordfilm в родную сетку Yoru. Для сериалов открывается корень указанного сайта: раздел выбирается в его меню, неизвестный адрес категории не придумывается.

Есть отдельная кнопка браузера, если пользователь предпочитает свой браузер. Cinemeta и Internet Archive сохранены в списке каталогов; выбранный источник запоминается отдельно для фильмов/сериалов. Родные фильтры и поле поиска скрываются, когда используется каталог сайта: они не объявляются фильтрами Lordfilm. В карточке другого каталога Lordfilm тоже можно выбрать источником — откроется каталог, где нужно найти нужный фильм.

Окно Lordfilm сохраняет sandbox/contextIsolation/webSecurity, не получает Node и preload/IPC приложения. Новые окна и загрузки блокируются; навигация главного документа ограничена точным HTTPS origin `sm.lordfilm5.pro`. Вложенное видео может загружаться со своего сервера. Работает прежняя локальная рекламная защита. Права камеры/микрофона и другие разрешения не выдаются; полноэкранный режим, F11/Esc разрешены окну просмотра.

## Постеры и оценки без ключей

Поле OMDb удалено вместе с конфигурацией, IPC-методами и реализацией запросов OMDb. Старый зашифрованный файл ключа, если он был создан прежней версией, больше не читается и не используется. Приложение не просит личные API-ключи для кино, постеров или рейтингов.

IMDb приходит из Cinemeta по точному IMDb ID. Для карточки с привязкой Кинопоиска в первую очередь используется постер по **её числовому KP ID**: публичный адрес `st.kp.yandex.net/images/film_iphone/iphone360_<ID>.jpg`, затем проверенный постер из открытой карточки и прежние источники. IMDb/MAL/TVmaze ID не подставляются вместо KP ID. Ручная привязка остаётся пользовательской; автоматическая помечается подтверждённой только при точном совпадении IMDb. Смена и очистка привязки обновляют постер и оценку КП в открытой карточке и сетке.

На открытой странице Кинопоиска проверяются тип, числовой ID и идентичность произведения: точный IMDb при наличии либо точные название и год. Оценка Кинопоиска подписана **КП**, а не IMDb. URL постера проходит проверку протокола и разрешённых CDN.

Оценка критиков Rotten Tomatoes берётся из публичной страницы, найденной поиском по названию/году, после проверки Movie/TVSeries, идентичности произведения и канонической страницы. Читается явно обозначенный critics/Tomatometer score; зрительский aggregateRating за него не выдаётся. Реальные 0% сохраняются, отсутствующая оценка не создаётся. Оценки показываются в карточке и в уже загруженной сетке после получения. Глобальный фильтр и сортировка по RT удалены: публичные страницы не дают подтверждённого полного рейтингового индекса.

Запросы ограничены по размеру/времени и кэшируются до суток; отрицательный результат — до часа. При 403/429 или проверке человека источник не опрашивается 15 минут. CAPTCHA и SSO не обходятся. Работа без API-ключа не означает неограниченного доступа к чужому сайту.

## Сериалы

Из кино/сериалов исключаются явный жанр Anime/аниме и японская анимация по жанру/типу и языку/стране. Из сериалов также исключаются News, Talk Show, Reality, Game Show, Sports, Variety, Award Show и Panel Show. Японские игровые фильмы и западная анимация сохраняются; название само по себе не используется для догадки. Фильтр применяется к сетке, поиску и восстановленному кэшу. Родной раздел «Аниме» не меняется, пользовательская библиотека не удаляется.

TVmaze по-прежнему использует эфир США и веб-премьеры последних трёх дней; подходящие сериалы упорядочиваются по весу TVmaze и его оценке. Это не глобальная популярность IMDb. Кэш каталога обновлён до v2, чтобы не переносить старую выдачу с новостями и аниме.

## Проверки и границы подтверждения

147 unit-тестов, production build, 46 целевых browser-сценариев (кино, каталог и автоматические источники аниме) прошли. Дополнительно повторены сценарии привязок, их очистки и настроек без ключей. Настоящий Linux Electron проверил точный адрес Lordfilm и переход внутри него, отсутствие Node/IPC, блокировку другого origin, реальное собственное H.264/AAC видео 1080p, кнопку fullscreen и F11/Esc, браузерный путь, а также прежние движки, субтитры, аниме, автопереход и кино. Каталог/HTML Lordfilm и ответы источников в этих тестах контролируемые; это не проверка реального фильма на Lordfilm.

Из разрешённой облачной сети реальная карточка https://www.kinopoisk.ru/film/326/ ответила HTTP 302 на Yandex SSO. Метаданные такого ответа не приняты за подтверждённую карточку. Lordfilm, CDN постеров и Rotten Tomatoes пока не разрешены активной политикой облачной среды (ревизия 6): живой доступ и воспроизведение из разных стран не подтверждены. В сетевой черновик добавлены точный домен пользователя, CDN Кинопоиска и домены Rotten Tomatoes; черновик сохранён, но не применён.

Для живой облачной проверки нужно проверить/сохранить сетевой черновик в настройках среды и опубликовать среду. Это технически отдельный шаг от сохранения черновика. [Cloud environment runtime SKILL.md](skill://plugin_connector_1p_c5b7d5df5d7081918f2c4be5a633ed5d/cloud-environment-runtime/SKILL.md) требует: “Configuration changes require the environment configuration workflow and its user review.” Это ограничивает проверку из облака, а не сеть установленного приложения на компьютере пользователя.

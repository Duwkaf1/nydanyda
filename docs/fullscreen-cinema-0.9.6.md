# Yoru 0.9.6 — полный экран, кино и публичное скачивание

## Что вызвало проблемы

Общий обработчик разрешений Electron отвечал отказом на `fullscreen`. Это воспроизведено в настоящем приложении: нажатие кнопки вызывало запрос, но документ не переходил в полный экран. Дополнительно кинозал ограничивал высоту контейнера 76vh даже при полноэкранном состоянии. В 0.9.6 разрешение fullscreen выдаётся только созданным Yoru окнам плееров, остальные разрешения остаются закрыты. CSS полного экрана заполняет ширину и высоту viewport для обоих движков и iframe. F11 переключает режим, Esc выходит; источник, пауза и позиция сохраняются.

Карточки кино раньше предлагали поиск на YouTube первым вариантом. Это не был подтверждённый поток полной серии. Теперь основными вариантами являются плееры CX/SBS/CFD/SSpoisk/KinoKino, а поиск на YouTube, Кинопоиске, Rutube и VK остаётся отдельным выбором.

Репозиторий переименован в `Duwkaf1/nydanyda` и публичен. Прежние ссылки скачивания вели на артефакты Actions с ограниченным сроком хранения и требованием входа в GitHub. Новый этап выпуска после успешных Windows-проверок сверяет SHA-256 реального установщика и публикует EXE, его контрольную сумму и переносимый ZIP в GitHub Releases. Публикация происходит из черновика после загрузки всех файлов. Публичные файлы Releases доступны без аккаунта; опубликованные версии не перезаписываются другим коммитом.

## Как открыть фильм или сериал

В карточке выбери источник просмотра. Для точной карточки Кинопоиска реализованы преобразования:

| Источник | Пример страницы сериала |
| --- | --- |
| CX | `https://kinopoisk.cx/series/1235052/` |
| SBS | `https://kinopoisk.sbs/series/1235052/` |
| CFD | `https://kinopoisk.cfd/series/1235052/` |
| SSpoisk | `https://www.sspoisk.ru/series/1235052/` |
| KinoKino | `https://kinokino.vip/series/1235052/` |

Для фильма используется `/film/ID/`. Пример ID взят из пользовательского сообщения: он не объявляется подтверждённым соответствием сериалу Under the Dome или другому названию.

Автоматический подбор принимает только структурированные данные с тем же IMDb ID и типом карточки, с единственным KP ID. Совпадение по похожему названию и подстановка цифр IMDb вместо KP ID не используются. При недоступном подборе можно вставить ссылку Кинопоиска или ID. Ссылка сохраняется только для этой карточки; пустое поле удаляет привязку, неподходящий тип не запускает прежний ID. Поздний ответ закрытой карточки не меняет новую.

Плеер открывается в отдельном окне Yoru с sandbox/context isolation/webSecurity, без Node/preload/IPC у сайта. Новые окна и скачивания сайта запрещены, офлайн-защита от рекламы сохранена. Кнопка полного экрана сайта и F11/Esc проверяются отдельно. Качество, перевод, сезон и серия выбираются внутри источника. Неподтверждённые параметры `season`/`episode` в URL не добавляются; автоматическое управление сериями/таймингом этих сайтов не объявляется готовым.

## Проверки GitHub

В уведомлениях пользователя показаны исторические падения: №34 упал на unit-тестах, №30 — на проверке настоящего desktop-приложения. После них сборки №35, №36 и №37 завершились успешно; история прежних неудач не удаляется и не выдаётся за текущие ошибки. В новой сборке Actions обновлены до текущих версий с Node 24. Для изменений только Markdown/документации Windows-проверка не запускается; новый запуск ветки отменяет устаревший незавершённый.

## Границы живой проверки

Живой запрос `kinopoisk.cx/series/1235052/` получил отказ прокси 403. Канонический поиск Кинопоиска перенаправил на SSO Яндекса, дальнейший переход также закрыт средой. SBS/CFD/SSpoisk/KinoKino не разрешены действующей политикой сети revision 6; они добавлены в сохранённый черновик для публикации пользователем. Поэтому этот выпуск подтверждает интерфейс, безопасное формирование адресов и работу плеера на собственном видео, но не доступность конкретного фильма/озвучки/серии у каждого зеркала и в каждой стране. Подписка, вход и DRM сайтов не обходятся.

По [cloud-environment-runtime](skill://plugin_connector_1p_c5b7d5df5d7081918f2c4be5a633ed5d/cloud-environment-runtime/SKILL.md), «Configuration changes require the environment configuration workflow and its user review». Живая проверка новых зеркал требует публикации сетевого черновика.

## Проверки выпуска

125 unit-тестов и production build прошли. Настоящий Linux Electron проверяет H.264/AAC 1080p, полный экран обоих движков, вложенный оригинальный аниме-iframe и фильм, сохранение времени/паузы, F11/Esc, а также изолированное окно зеркала с настоящим декодированием собственного видео. Карточки и полноэкранный режим дополнительно проверяются в браузере. Внешние ответы в этих сценариях контролируемые; они не подменяют живую проверку зеркал.
